# Rubric map: each Build Stage criterion, what is built, and where to check it

Written from the code on 2026-10-29 for the judge guide (the assistant answers judges from this file and never claims more than the status here). `tests/assistant/test_rubric_map.py` checks that every code and test path exists, that every status is one of the five below, and that every slide and video time exists; `python scripts/check_claims.py` lists every place where the deck or the video script uses a stronger status word than this file.

Statuses, strongest first:

- **Built**: the code exists, has tests, and runs in the demo.
- **Partly built**: some of it is built; the known limit names what is missing.
- **Simulated**: it runs, but what you see comes from simulated data or simulated users.
- **Mock**: the interface exists, but a stand-in answers instead of the real service.
- **Roadmap**: not built.

Slides and video times are PROVISIONAL until the final deck and video exist: slide numbers follow `docs/submission/slides.md` (built from the deck source) and times follow `docs/submission/video_script.md` (the shooting script). Numbers about classes, evals and cost are not typed here: each row points to the generated file that holds them.
